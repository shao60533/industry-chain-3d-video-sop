版本 video-2.2，2026-10-04。现行制作入口；发布按[视频发布SOP](publication-sop.md)。质量验收2.2进一步核报告内容/覆盖、功能焦点、全部依赖和实际提交入口。执行以本文件与共用验收规则为准。

2026-10-07制作复核补充：先按[制作复核执行卡](review-checklist.md)审稿、看图和确定返工范围。修一处共性错误须检查全期同类内容。封面可独立制作，覆盖旧“必须与正片模型同源”的限制；正文高清图、可编辑模型与动作仍须对应。规则写入不代表美术问题已解决。

## 1. 任务契约与现行选择

- 每片独立 `job.json`，写 topic、source版本/ID/哈希、content_key、目录、mode、平台账号、分工、时长预算、已接受选择、发布授权。版本变化不改变同一公开内容的身份。
- 默认 `produce_only`。制作、学习、复盘或准备下一集均不授权公开提交。用户既有明确授权在原范围内持续有效，不重复询问；重新发布、换内容或改已指定发布时间按实际新增授权处理。
- 来源为用户指定版本的 完整产业链原稿；先读全文再映射。不用关键词命中的旧概念板块代替，不自动增加网页财务数据。缺失事实列入内部缺口，缩小判断；用户要求补查才扩展研究范围。动效教程和行文样本仅用于方法学习。
- 单人旁白，使用获授权且经试听接受的音色；如任务指定本人音色，复用本地参考。新的云端上传个人录音须有明确目的地授权。
- 音色参考由使用者本地配置：`private/voices/owner/reference-clean.wav` 与对应文本。仓库不含个人录音、音色资产或其哈希。
- 不固定所有影片1.1或1.25倍。每种音色/供应商先用含公司名、数字、缩写、判断句的30–60秒试听决定实际语速和停顿。时间过长先减次要公司与数字或拆集；音高与音色保持稳定。自然聊天、偶尔反问，判断句留停顿；不默认双人机械问答。
- 字幕与关键文字使用共用video-acceptance/safe-layout.default.json，每期复制并锁定字体与布局SHA。保守预留不冒称官方坐标，实际界面验收仍必需。
- 小红书竖屏基线1080×1920、24fps，约5分钟/集为制作预算，按最终旁白实测。早期就决定是否上下集，分别有开头、结论、封面、字幕与冻结包。
- **Codex 是默认主执行者**：负责需求拆解、读源、稿件与分镜、建模脚本、配音/渲染工具调度、问题修复、证据归档和交付复核。专业工具通过本地或已配置的适配器执行；可选其他模型只承担明确分配的子任务。既有工具名称不构成强制供应商依赖。Codex 自检如实记为 self_review；没有实际听看或设备证据的项目保持 pending。操作入口见 [Codex 工作流](codex-workflow.md)。

## 2. 写稿：每层必须给出判断

第一句口播使用自有品牌问候，例如“大家好，这里是[品牌]。”。紧接本期产品与“谁卡脖子，谁赚钱？”悬念，说明拆开产品的行动。不要用定义、行业背景、买卖关系或第二遍流程说明冲淡开头。已接受的中段不因学习新风格自动重写。

每个环节沿这一条因果链写：

**是什么、用在哪 → 解决什么问题 → 关键结构/工序 → 技术门槛 → 具体瓶颈判断 → 对应公司的竞争位置与经营数据 → 靠什么赚钱、主要成本与风险 → 下一层。**

- 产品分类只用一套主轴。先讲使用场景，再映射技术类型；如HBM是DRAM的一种高带宽产品，不能与DRAM、NAND并列成同层分类。先讲HBM的作用，再讲DRAM裸片、TSV和键合的实现。
- “是不是卡脖子”必须给出有证据的对象、结论和原因，例如哪款产品/哪道工序供应集中或量产落后、哪家公司已具备替代条件。不能只列“性能、良率、产能是否达标”的通用问题。证据不足就明确哪项判断暂不能做，不空填观点。
- 每家公司单独判断：提供什么、对谁有价值、与谁竞争、目前强弱证据、收入与利润机制。长鑫与长江存储按各自产品判断；不同赛道公司不能仅因同属存储就直接排名。
- 竞争比较选2–3个真正支撑结论的数据；同业务公司竞争比较才让数字同屏，其余关键名字与数字随叙述揭晓、及时退场；规模、份额、技术进展、盈利、业务占比优先，估值按需要使用。期间、单位、分母与估算属性留在来源映射和必要画面备注；不在口播里连续解释“口径”。不同期间不能省掉差异后伪作同口径比较。
- 视频就是分析，直接说判断。删“原报告认为”“每家公司先看……最后看……”等制作说明；删“最贵的不一定最复杂”等没有具体对象与结果的泛泛转折。
- 删除或重写空泛句后，复查所有环节的同类句式与公司判断，不只修被点名的一段。比较公司须分别给出结论；不能把一套“看性能、良率、产能”的提问复制给所有公司。保留完整产品路径，不能漏掉原稿中的整机/终端层。
- 成本占比支撑价值量，盈利判断用经营数据和商业机制。不要在每次说成本后追加“这不等于利润”的自我否定；内部审稿检查二者是否混淆，口播正面解释如何赚钱。
- 开场后、产品介绍前明确本期3–4个具体问题，参考光互连的“组成／公司／价值与赚钱”提问结构，按本期主题调整。结尾回到同一产品，按同一顺序用具体部件、公司、瓶颈与盈利机制回答。视频提问卡随口播逐条出现，结尾有对应回答卡；不能仅写进文字稿或分镜。不要另加概念名单核对或选股提醒来替代收束。
- 默认可编辑Markdown/TXT；不自动制作Word。导出稿与当前script.json同版本，同一次修改更新语音文本和镜头依赖。

`B-script`保存script.md、script.txt、script.json、script-lock.json、company-judgments.json、source-map.json。稿件确认后记录真实确认依据与SHA；之后仅改获准段落，不把自评伪造为用户确认。

## 3. 开头动效、音效与封面

开场沿产品特写、展开、短环绕、合体、标题的动线制作。参考教程用于学习方法，工具能力和效果以实际样片确认。

- 沿用已接受的无口播8–10秒视觉签名，接第一句个人旁白。先独立做短样片验证；其对留存的收益尚未有对照实验，不能把更长品牌动画自动算作优化。
- 动线：主角特写 → 本期公司快闪 → 真实分层展开 → 短悬停、小幅环绕 → 真实合体落拍 → 自有品牌和本期标题 → 正文。快—慢—快，展开先避让外层，再让内部运动；由同一闭合装配坐标驱动展开和收回。
- 9.5秒/228帧为候选预算，时间轴按实际小样调整。候选节奏：0–60连续特写拉远/快闪，60–96展开，96–120短环绕，120–144平滑合体，144–228标题配慢运镜。动作连续性检查：不要用长时间复制静帧代替运镜；抽查镜头轨迹、重复帧、段落交接速度与完整播放。合体可延长收回段，保留已选音乐落点，不能只改帧率或靠插帧掩盖动作问题。
- 科技感优先来自实际分层空间、侧面透视、冷色边缘光和透明层可读性；可加克制轮廓辅助，但须注明其为美术呈现，不暗示部件实际发光。放大展开距离后重验层序、穿插、构图、最大视角与闭合复位；完整模型与零件数量保持一致。
- **2026-10-03用户校准：开头以有节奏、有旋律推进的音乐为主。** 鼓点、低音与旋律贯穿开场，先依据音乐拍点安排快闪、展开与合体；悬停时降低配器密度但保留律动，合体落重拍，品牌动机接标题。whoosh/click/短撞击只点缀动作，不能把零散音效加弱持续音当作节奏音乐。先做音乐与动画的小样试听，再扩片；BPM随本期镜头确定，不固化光伏候选120 BPM。
- 音乐拍点、动作、轻音效共用帧号，关键合体落点起始容差±1帧，最终以听看同步为准。保留独立音乐、动作音效与混音分轨，旧候选不覆盖；核编码后响度、峰值、音画延迟，数值检查不代替实际听感。
- 开头无旁白时可突出音效；接入人声前降下音乐/残响。对白段检查音乐与SFX遮盖、瞬态峰值、拼接点击；沿用-18 LUFS/-1.5dBTP作混音起点，不把响度数字替代实听。
- 静帧推近**不算合体**。新样片须看到各层回到原装配位置、部件不变形、不新增、连接关系正确，全程无穿插；缓慢环绕也须是实际相机运动。
- 封面保留系列“拆开一[量词][产品]”主标题，下面“谁赚钱？谁卡脖子？”，具体沿用用户确认用词。单独设计主焦点、透视、材料与照明，可从模型另设镜头，也可独立生成封面；不要求取自视频或复用同一模型。主题和结构示意身份须准确，文字逐字核对；生成图不充当厂商照片、工艺剖面证据或可编辑建模交付。验收9:16/3:4裁切及缩略图，正文模型仍独立验收，不能由更漂亮的封面抵消其缺陷。

## 4. 先图、分件建模、短样片，再全片

**视觉质量校准（2026-10-05，2026-10-07修订）：** 按[光模块视觉基准](visual-quality.md)执行。先独立设计封面构图，再做同源模型的整体/展开/功能近景与15–30秒正文样片；使用实际发布基准，同宽200/390px比较产品焦点、装配细节、材料/光影和标题层级。不能以零件齐全、4K或查过官网代替产品感。封面在裁切之外必须评审主体可辨、材料层次、画面看点和系列排版；具体质量以当前版本图和代表片段为准。

每镜头列原生动作、末帧保持、静态底图和二维变化的实际区间，再按口播功能窗检查输入→传递→输出。clip存在不等于整段动作覆盖；模型放大出画、实体进入标题区、数据卡统一缩小主体均须重新构图。财务段允许合理停留，不用静态比例自动评美术。制作与复核分别记录；手机免验不降低本地美术标准。问题只有新版图和代表片段达到基准后才关闭。


先锁整体、拆解、内部三类参考图，生成图只是美术参考；结构依据来自事实包与可说明的通用原理。错误层序、悬空连接、重复接口及无依据的厂商尺寸不能进入模型。`design-lock.json`记录图/哈希、材质、光源、镜头、组件和排除项。

细节按近景可见的功能关系增加：焊盘与键合、层间互连、TSV绝缘层、微凸点、基板走线/过孔、定位与紧固、腔体气路与载台。对象数量、随机堆料、采样数或4K分辨率不能证明专业感；同机位对照已接受的光互连基准。

**2026-10-07芯片细节校准：** 基板不能只剩几根线；按选定产品结构呈现器件/焊盘、过孔、走线与供电区域、定位标记、边缘层叠及连接落点。裸片/晶圆需有差异化功能分区、尺度层级、阵列/逻辑纹理、划片道与边缘关系；表面可见图案和微观层剖面分开，不把晶体管尺寸结构画成裸眼可见凸块。器件、层叠和纹理按本期作用取舍，通用示意不得暗示真实厂商版图。既看原尺寸近景，也看成片200/390px能否辨出看点；细节存在却没拍清仍返工。

**2026-10-03产品模型校准：** 开场产品爆炸图与口播做部件覆盖表，逐项记录“讲到的部件→语义节点→展开位置→标签→正文镜头”。内部讲到的部件要实际建入同一个装配，并在最大展开时可见；关键互连、输出总成不能被外壳或透明层遮住。上游材料、制造设备和外部系统用后续镜头承接。先按厂家手册、产品图或剖面确认功能细节，再优化栅线/焊点、孔槽、拼角、密封、插接等结构和材料；模型、高清图与动画同源。通用微尺寸与美术辅助单独说明，不能声称厂家CAD。用户认可动效时只冻结该方向，仍可按反馈重做产品细节。材质节点按type或自定义语义ID查找，避免界面语言导致失配；闭合态未使用、展开仍需要的材质要保留持久引用，保存后重新打开检查。图注落点核对最终可见表面，不能只靠锚点位于画面内就判准确。

`shot-map.json`每镜头含 `shot_id / script_segment_id / source_refs / start_ms / end_ms / product_part / company / model_asset / semantic_nodes / action / camera / reveal_company_ms / overlay / caption_ids / crop_intent`。先展示解决问题的部件和过程，再揭晓公司，给真实动作留时间；仅转外壳或更换名字不算公司镜头。优先产品细节和进入内部的镜头，随后揭晓公司名；不恢复固定左右栏与PPT大段文字。

**正文子模块校准：** 近景需要同时满足结构正确和成片可见。空腔、端子/电极与母线的连续连接、绝缘间隔、定位、气路、散热与密封按功能关系检查；外盖应真正让开。全景中的小零件看不清时补同源近景，而不是再加更多不可见对象。

**原生动画保存：** 从未插入动画曲线的工程先捕获全部姿态，再统一写入关键帧。边计算边插入可见性曲线会让上一帧动画覆盖下一次姿态；修改集合对象可见性前先固定对象列表，避免迭代时集合更新。保存后重新打开，按每段动作的起止状态复核变换、相机与可见性。

**配音提示绑定：** 公司数据卡按实际语音与所属环节绑定。年份、“我的判断”等重复短语必须标明出现次序或采用公司语义锚点；检查卡片是否提前跳到下一家公司。结构片段的完整动作长度不能被下一个提示截断。

模型与渲染检查：

**官网产品参考（2026-10-04人形机器人反馈）：** 产品图从相关公司官网产品页、技术资料或官网下载中心读取，并记录产品名称、页面网址、原图网址和实际查看结果。整机外观与功能部件分别找对应参考；官网外观照片只能支撑比例、曲面、分件和可见接口，内部传动关系按官方结构图或手册确认。不能把无来源概念图、二次搬运图当成熟产品依据。

**先验产品完成度，再出高清：** 同机位检查整机轮廓、躯干/四肢/手的比例、曲面过渡、壳体厚度和分件、关节承力连接、装配间隙、线束和维护接口。局部看真实齿形示意、轴承、螺钉凹槽、触点与热界面。明显方条拼装、悬空连接或仅靠画线/材质模拟必需结构时，先修几何；高分辨率、采样数、对象数不能代替此项。用户指出粗糙后提供旧/新同机位对照及官网参考，稿图批准仍待用户明确确认，不将制作者自检写成用户认可。

1. 统一米/毫米换算，明确世界/局部坐标；读取变换前更新view layer。父对象与子对象只应用一次位移，不从上一动画终态累加新基位。
2. 用语义ID定位零件，地台/灯/相机排除；不要用“最低对象”猜产品。导出后再检节点规范化，缺节点立即报错，禁止静默跳过。
3. 壳体是真实开口；盖孔与底座共享装配坐标；透镜、接口、键合端点按连接关系验收。闭合、最大展开、合体、资产交接逐态检查，交接只保留一个外壳。
4. 金属先看反射光源形状与渐变，再调粗糙度/拉丝；平面与曲面分别处理法线。不同场景重设灯光目标、尺度、曝光；不能只加发光或功率补救。玻璃与实体分离，有依据的可见层次优先。
层压透明材质另查闭合态与最大环绕角：电极嵌入胶膜、玻璃与胶膜界面接近时，不能仅凭展开态清晰就放行。异常先查交叠界面与法线；结构示意可用记录在案的薄片光学近似，保留实体厚度，不冒称光学仿真。改材质后重做受影响静帧与动作缓存。

5. `.blend`打开后实际启用Metal并确认设备；Remotion使用与依赖一致的arm64 Node。先测少量帧的实际耗时与可用磁盘，不让多个Blender任务争同一GPU。
6. 动作共用连续帧时间。正交静帧推拉只可复用没有结构动作的镜头；逐帧动作、相机和锚点以同一pose计算。所有JPEG采用统一尺寸/色度格式，合成前检查，避免420/444切换导致ffmpeg重建滤镜丢叠层。
7. 使用依赖哈希复用已验收镜头。输入包含稿段、最终语音、部件、灯光、机位、材质、叠层及速度；修改只重做受影响部分。字体、布局profile、渲染器和合成方式均进入缓存键；文件存在不能证明缓存有效。偶发崩溃保留日志，有限重跑，不把重复失败当正常队列。

## 6. 成片验证与恢复

- 1080×1920 H.264/AAC、固定24fps；全解码、实际时长/帧数/PTS、意外黑帧、章节边界、JPEG格式边界检查。数字检查不能替代观看运动。
- 字幕最多两行，加载实际字体测量墨迹宽高，按词/标点断句，保护中文术语、专名、数字及英文缩写；无法放下按最终音轨拆页，不能一味缩字号。标题、卡片、标签、字幕错开，公司切换旧标签退场。
- 共用1080×1920候选：字幕x64–880/y1388–1532，卡片y980–1350，底部1560以下及右侧x900–1080/y460–1560预留。是保守制作配置，不是平台官方固定规范；各渲染器读同一profile，实际设备正常播放仍查字幕、数字与功能连接。
- 验全部字幕及卡片同屏区间并导出layout.jsonl，不能只测开场。最终MP4再取单行/两行长句、四问/四答、财务卡、图注、各章进出与转场，生成360/390宽带遮罩图；墨迹越界、卡片相撞、平台遮挡失败即返工。
- [可执行验收规则](acceptance.md)规定technical_passed、layout_passed、release_ready独立记录。12项证据含内容判断、本人音色、模型覆盖、开场节奏、技术、几何、编码遮罩、动态播放、实听、真实界面和封面。缺项/pending/旧SHA不能放行；脚本不伪造主观检查。
- H manifest含production_acceptance的evidence/profile绝对路径与SHA；先运行video_publish_preflight.py，非零退出不得启动publisher。本地质量前置与平台MAIN的身份、账号、真实chips/群聊/封面/AI/时间/单次attempt分别验收。新xhs_video_prepare/publish已强制在网页写入前及上传/attempt前重查质量；旧status/focus仍只读。离线入口测试与首次授权生产分开。
- 从最终WAV生成对齐；变速后重算字幕与镜头。ASR只作漏句/疑点筛查，专名谐音不能自动判发音合格；实听状态没有证据时写“待听”，不冒称全片实听。
- 每章节看进入、内部动作和退出；额外检查所有结构交接、快慢转场、爆炸/合体落点、首尾与上下集接缝。记录检查者、片段、结论和未检查范围。
- JPEG输入为全范围，交付H.264需显式转换色彩范围与矩阵，并从最终MP4确认yuv420p、有限范围和BT.709的矩阵/原色/传递特性三项标记；仅指定pix_fmt不保证范围正确。只改编码时复用合成帧，保留前次文件、失败记录与缓存依赖修订证据。
- 任意成片/封面/文案替换重新冻结，旧哈希验收失效。文件名未变也重算SHA；历史报告保留并补充标明不对应新版。未改音轨/模型可附依赖SHA复用对应检查，布局改变仍重验编码画面。改字体不配音；改语气重对齐；改判断重审来源；改模型只重相关镜头。
- 工程脚本优先用当期参数；其他任务的脚本可能含固定路径/帧号，不能当通用一键命令。已有可复用函数与运行器能力按实际验证列出，不杜撰 `video run`。

跨平台另建发布包：保留母版，按当前账号页面确认码率、色彩/音频及封面槽；转换后校验帧数、同步、色彩和裁切。公开资料或旧平台成功不证明新平台能发布；浏览器拒绝与超时分别记录，不推断账号问题，不绕过安全策略。

## 2026-10-04：原帖视频替换的画面复核补充

同一原帖更新须绑定原note_id、已授权动作和最终媒体SHA；保存前后保留并核对封面、标题、正文、真实话题chip、群、AI声明及可见性。打开编辑页、看到重新上传入口、浏览器仍可读或后台旧审核状态，均不是更新成功回执。系统锁屏单独记阻断，不反复调用原生应用，也不重发新帖补救。

JPEG全范围转换后显式设置编码器的colorprim、transfer和colormatrix；最终文件再次独立核四项色彩字段。旧报告与新版实际解码图一致的部分可用逐帧SHA证明复用，其余直接复核；不直接更改旧报告的媒体SHA。
