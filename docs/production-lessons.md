## 语义配音计划的用法

本仓库提供计划与证据验证，不提供TTS供应商。完整说明见[声音与时轴](speech-production.md)。先把确认稿整理为Markdown标题与自然段，正文各段之间空一行；字幕分页不决定合成边界。

```bash
python3 scripts/speech_plan.py --script jobs/example/B-script/script.md --out jobs/example/D-audio/speech-plan.json
```

规划结果保持pending。在实际合成、对齐和逐段连听后，才把当前script/audio/timing SHA、边界/语速审阅和逐段真实证明写入计划，再按既有D步骤登记输出与证据。C/E仍按既有版本批准范围执行，不为填写新字段重复索取相同批准。

## 声音、数字与缓存共同维护时轴

新增停顿=max(0，目标语义停顿−两段已有首尾留白)。测量应保留真实呼吸，不按单一静音阈值全删。改旁白、语速或停顿使对齐、字幕、镜头落点、产品标注、混音与编码证据失效；只改显示数字时，保留旁白与原词时点，验证原句映射。

数字保护示例：112%与2.98个百分点区分，65.7亿元与8038万元保留单位，400G、10U及型号不能拆行；“一体化、同一套、一层层”保留原词。显示字符缩短后，不得按新字符长度推进原对齐游标。按全量数值/单位等价检查，再看最终编码难例，不能只随机抽一行。

开场音乐、动作、快闪与标题共用事件帧。最终解码后测实际声能/起音误差，再分别记录连续听看结果；±1帧是对齐起点，不是音乐质量评分。无需将所有产品固定在120 BPM或某个历史帧号。

## 发布适配的可复用经验

配置文件、模型能力声明、实际进程、后台接收器与平台回执是不同层次。只有源码修好或离线测试通过，不能宣布平台全链可用。后台能力要求来自本期job约束；适配器应在写页/上传票据/attempt之前核实际能力，不暴露被约束禁止的前台工具来“兜底”。

基础正文与发布工具的序列化话题字段分开。页面只写正常正文，再选择真实候选chip并核顺序/数量；不要把`[话题]#`占位序列直接写进内容。追加前查看已有空段，修同一未提交草稿时保留身份和冻结依据，不能为迁就错误页面修改expected。

具体话题数量、活动名称、期限和入口由任务与当次平台决定，仓库不固定短期活动偏好、不保证流量。用户临场修改的原创/封面等设置应以同包SHA的补充记录留证，不覆盖原manifest；结果未知、归档失败和审核中都不能触发重发。

## 保持原12项与证据层次

不新增第13项报告。visual_contract进入C，speech_plan进入D；真实性/标注进入model_coverage，运动/交接进入dynamic_playback，字形/引线进入layout_geometry，手机编码进入encoded_masked_review，段落韵律/拼接进入voice_music_listening。

自动核心只验证文件、身份、覆盖与当前版本依赖；真实语义、表面可见、声音、连续播放和设备需实际观察。没有相关能力的项继续pending。合成回归不是生产证明，公开包仍不签发release_ready。当前验证范围见[verification](verification.md)。
